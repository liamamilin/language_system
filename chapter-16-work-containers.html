18  第 16 章：Work 的 Container 示例（Work Containers）

18.1 本章要解决的问题

第 15 章梳理了 Work 做事单位下的 8 个 Group。本章继续向下一层推进，展示每个 Group 下可以放置哪些 Container。

做事是概念安置系统最直接的验证场——一个概念安置得够好，做事时就会自动调用。反过来，做事时遇到的困难，常常指向某个 Work 容器需要调整。

18.2 Goal 目标：Container 示例

18.2.1 Process Goal 过程目标

Process Goal 关注行动本身而非结果。“每天写 500 字”是过程目标，“完成一本书”是结果目标。

收纳 RU：daily practice、consistent action、habit target

主体增益：过程目标帮助主体从”结果不确定带来的焦虑”转向”行动可控带来的稳定感”。结果目标你无法完全控制，过程目标几乎可以。

常见用法：

常见搭配： - set a process goal 设定过程目标 - focus on the process 关注过程 - achieve a process goal 达成过程目标

常用句型： - I set a process goal of writing 500 words per day. 我设定了一个每天写 500 字的过程目标。 - Process goals keep me moving even when the outcome is uncertain. 过程目标让我在结果不确定时也能持续行动。

概念安置卡：

RU 名称：Process Goal

主位置：Work → Goal → Process Goal

关联位置：
- Mind → Learning → Deliberate Practice
- Mind → Desire & Motivation → Intrinsic Motivation

关联动作：set, track, maintain, adjust

关联属性：achievable, challenging, consistent, abandoned

说明：Process Goal 是行动关注目标单位。它帮助主体将注意力从不可控的结果转向可控的行动。

18.2.2 Outcome Goal 结果目标

Outcome Goal 是以具体结果为导向的目标。“完成一本书”、“赚到 100 万”、“减重 10 公斤”都是结果目标。

收纳 RU：target result、performance goal、achievement metric、desired outcome

主体增益：它帮助主体区分”我在行动”和”我的行动有没有产出结果”。过程目标让你持续行动，结果目标让你检查方向是否正确。好的目标系统需要两者配合。

常见用法：

常见搭配： - set an outcome goal 设定结果目标 - measure progress toward the outcome 衡量结果进展 - the outcome goal is clear 结果目标清晰

常用句型： - My outcome goal is to finish this book by December. 我的结果目标是在十二月前完成这本书。 - Outcome goals tell you where you are going; process goals tell you how to get there. 结果目标告诉你去哪里，过程目标告诉你怎么去。

概念安置卡：

RU 名称：Outcome Goal

主位置：Work → Goal → Outcome Goal

关联位置：
- Value → Importance → Priority
- Work → Project → Milestone

关联动作：set, measure, achieve, revise

关联属性：specific, vague, achievable, aspirational

说明：Outcome Goal 是结果导向目标单位。它帮助主体明确想要达到的具体结果。

18.2.3 Learning Goal 学习目标

Learning Goal 是以能力提升为目标而非结果的目标。它不是”完成项目”，而是”通过这个项目学到什么”。

收纳 RU：skill development target、mastery goal、competency objective、growth goal

主体增益：它帮助主体区分”我做完了”和”我从中成长了什么”。学习目标保护主体在失败时仍然有收获——即使结果目标没达成，学习目标可能已经实现了。

常见用法：

常见搭配： - set a learning goal 设定学习目标 - focus on the learning goal 关注学习目标 - the learning goal was achieved 学习目标达成了

常用句型： - My learning goal for this project is to improve my public speaking. 我这个项目的学习目标是提升公开演讲能力。 - Learning goals keep you growing even when outcome goals are not met. 学习目标让你在结果目标未达成时仍在成长。

概念安置卡：

RU 名称：Learning Goal

主位置：Work → Goal → Learning Goal

关联位置：
- Mind → Learning → Deliberate Practice
- Value → Benefit → Skill Gain

关联动作：set, pursue, achieve, reflect on

关联属性：skill-focused, knowledge-focused, measurable, qualitative

说明：Learning Goal 是能力成长目标单位。它帮助主体在做事的同时关注能力的实质性提升。

18.3 Plan 计划：Container 示例

18.3.1 Step 步骤

Step 是完成目标的顺序行动单元。一个计划的质量在于它的 Step 是否清晰、可执行。

收纳 RU：action step、next step、dependency

主体增益：Step 帮助主体把”我有一个大计划”转化为”下一步做什么”。好的 Step 是具体的、可执行的、有完成标准的。

常见用法：

常见搭配： - define the next step 定义下一步 - break down into steps 拆解为步骤 - the step is not actionable 这个步骤不可执行

常用句型： - What is the next step? 下一步是什么？ - If a step is not actionable, break it down further. 如果一个步骤不可执行，就继续拆解。

概念安置卡：

RU 名称：Step

主位置：Work → Plan → Step

关联位置：
- Work → Task → Single Action Task

关联动作：define, sequence, execute, skip

关联属性：clear, vague, critical, optional

说明：Step 是计划执行单位。它帮助主体将目标转化为可执行的具体行动。

18.3.2 Timeline 时间线

Timeline 是计划的时间坐标。它不是简单的截止日期，而是将步骤映射到时间轴上的完整序列——什么时间做什么、依赖什么前提、里程碑在何时。

收纳 RU：schedule、deadline、due date、time estimate、Gantt chart

主体增益：它帮助主体区分”我有步骤”和”我知道什么时候做哪个步骤”。没有时间线的计划只是愿望清单。Timeline 将抽象的步骤序列转化为可执行的时间承诺。

常见用法：

常见搭配： - set a timeline 设定时间线 - the timeline is realistic 时间线现实 - adjust the timeline 调整时间线

常用句型： - A timeline without buffer is a plan for failure. 没有缓冲的时间线是失败的计划。 - I need a realistic timeline that accounts for dependencies. 我需要一个考虑依赖关系的现实时间线。

概念安置卡：

RU 名称：Timeline

主位置：Work → Plan → Timeline

关联位置：
- Work → Project → Milestone
- Value → Cost → Time Cost

关联动作：set, adjust, track, communicate

关联属性：realistic, aggressive, flexible, fixed

说明：Timeline 是时间坐标单位。它帮助主体将步骤序列转化为有时间承诺的可执行计划。

18.3.3 Resource Plan 资源计划

Resource Plan 是完成计划所需资源的清单。它不是时间安排，而是对人力、资金、工具、信息和权限的前置规划。

收纳 RU：budget、team allocation、tooling、information need、access requirement

主体增益：它帮助主体回答”做这件事需要什么”。很多计划失败不是因为步骤不对，而是因为所需的资源没有提前安排。Resource Plan 把资源约束显式化。

常见用法：

常见搭配： - create a resource plan 制定资源计划 - the plan lacks resources 计划缺乏资源 - resource constraints 资源约束

常用句型： - A good resource plan identifies what you need before you need it. 好的资源计划在你需要之前就识别出了需要什么。 - Without a resource plan, you will be scrambling for tools and people mid-project. 没有资源计划，你会在项目中期为工具和人手疲于奔命。

概念安置卡：

RU 名称：Resource Plan

主位置：Work → Plan → Resource Plan

关联位置：
- Work → Project → Project Artifact
- Society → Organization → Company

关联动作：plan, allocate, secure, adjust

关联属性：sufficient, insufficient, over-budget, optimized

说明：Resource Plan 是资源前置规划单位。它帮助主体在执行前识别所需的人力、资金和工具。

18.4 Method 方法：Container 示例

18.4.1 Framework 框架

Framework 是结构化问题解决模板。它降低从零思考的认知成本。

收纳 RU：GTD、first principles、design thinking、agile

主体增益：Framework 帮助主体避免每次遇到同类问题都从头思考。一个好的 Framework 是”遇到 X 类问题，按 Y 步骤处理”。

常见用法：

常见搭配： - apply a framework 应用一个框架 - choose the right framework 选择合适的框架 - the framework does not fit 这个框架不适合

常用句型： - This problem needs a different framework. 这个问题需要不同的框架。 - A good framework reduces the cognitive load of decision-making. 一个好的框架降低了决策的认知负荷。

概念安置卡：

RU 名称：Framework

主位置：Work → Method → Framework

关联位置：
- Mind → Cognition → Mental Model

关联动作：apply, adapt, combine, discard

关联属性：rigid, flexible, proven, experimental

说明：Framework 是结构化方法单位。它帮助主体减少重复思考，将经验转化为可重复使用的模板。

18.4.2 First Principles 第一性原理

First Principles 是将问题拆解到最基础的不可再分的真理，然后从中重建解决方案的方法。它不是套用现成框架，而是从最底层的真相开始推导。

收纳 RU：fundamental truth、basic premises、deconstruction、reasoning from scratch

主体增益：它帮助主体区分”这个方法是这样的因为大家都这么做”和”这个方法从基本原理推导出来确实合理”。第一性原理思维让主体在现有方法失效时仍能构建新方案。

常见用法：

常见搭配： - think from first principles 从第一性原理思考 - break down to first principles 拆解到基本真理 - challenge assumptions with first principles 用第一性原理挑战假设

常用句型： - First principles thinking helps you break free from conventional wisdom. 第一性原理思维帮助你打破常规智慧的束缚。 - From first principles, I can rebuild the solution from the ground up. 从第一性原理出发，我可以从头重建解决方案。

概念安置卡：

RU 名称：First Principles

主位置：Work → Method → First Principles

关联位置：
- Mind → Cognition → Mental Model
- Language → Concept → Core Concept

关联动作：identify, reason from, test, apply

关联属性：fundamental, derived, verified, assumed

说明：First Principles 是底层真理单位。它帮助主体从不可再分的基本事实出发重建理解和方法。

18.4.3 Template 模板

Template 是经过预填充的标准格式。它不是从零开始，而是基于已有模式快速产出——周报模板、会议议程模板、项目计划模板。

收纳 RU：standard format、boilerplate、skeleton、blueprint、checklist

主体增益：它帮助主体区分”我每次都从头做”和”我可以复用之前的模式”。模板不是偷懒，而是把优秀的模式固化下来，把认知资源留给真正需要创造的部分。

常见用法：

常见搭配： - create a template 创建模板 - use a template 使用模板 - customize the template 定制模板

常用句型： - A good template reduces the time from start to first draft. 好的模板缩短了从开始到初稿的时间。 - Templates capture best practices so you do not have to rediscover them. 模板捕捉了最佳实践，让你不必每次都重新发现。

概念安置卡：

RU 名称：Template

主位置：Work → Method → Template

关联位置：
- Language → Text → Document
- Work → Task → Recurring Task

关联动作：create, use, customize, share

关联属性：reusable, one-time, flexible, rigid

说明：Template 是标准模式单位。它帮助主体复用已有的成功模式，减少重复性思考的开销。

18.5 Feedback 反馈：Container 示例

18.5.1 Error Feedback 错误反馈

Error Feedback 是从错误中提取的信息。它是改进效率最高的一类反馈。

收纳 RU：mistake type、failure mode、lesson learned

主体增益：Error Feedback 帮助主体把错误从”羞耻来源”转化为”改进数据”。系统化处理错误反馈是快速成长的核心机制。

常见用法：

常见搭配： - capture error feedback 记录错误反馈 - learn from errors 从错误中学习 - error feedback is actionable 错误反馈是可操作的

常用句型： - I need to capture error feedback from this project. 我需要从这个项目中提取错误反馈。 - Error feedback is most valuable when it is specific and actionable. 错误反馈在具体和可操作时最有价值。

概念安置卡：

RU 名称：Error Feedback

主位置：Work → Feedback → Error Feedback

关联位置：
- Mind → Learning → Feedback Utilization

关联动作：capture, analyze, apply, share

关联属性：actionable, vague, specific, general

说明：Error Feedback 是改进信息单位。它帮助主体将系统化地从错误中学习，而非回避或重复错误。

18.5.2 Positive Feedback 正向反馈

Positive Feedback 是确认什么做得好的反馈。它不是单纯的表扬，而是对有效行为的具体确认——让你知道应该重复什么。

收纳 RU：reinforcement、affirmation、recognition、strength confirmation、what worked

主体增益：它帮助主体区分”我在改正错误”和”我在巩固优势”。很多人只关注错误反馈，忽略了正向反馈的价值。正向反馈告诉主体应该重复什么行为，而不仅仅是避免什么。

常见用法：

常见搭配： - give positive feedback 给予正向反馈 - receive positive feedback 收到正向反馈 - positive feedback reinforces good behavior 正向反馈强化好行为

常用句型： - Positive feedback tells me what to keep doing. 正向反馈告诉我要继续做什么。 - The best positive feedback is specific about what worked and why. 最好的正向反馈具体说明什么做得好以及为什么。

概念安置卡：

RU 名称：Positive Feedback

主位置：Work → Feedback → Positive Feedback

关联位置：
- Mind → Learning → Feedback Utilization
- Relationship → Influence → Persuasion

关联动作：give, receive, seek, apply

关联属性：specific, vague, motivating, empty

说明：Positive Feedback 是优势确认单位。它帮助主体识别应该重复的有效行为，而非只关注错误。

18.5.3 Peer Review 同行评审

Peer Review 是由同等水平的人对工作成果进行的系统性检查。它不是上级评估，而是基于专业判断的同行互查。

收纳 RU：code review、design critique、peer assessment、manuscript review、quality check

主体增益：它帮助主体区分”我自己觉得不错”和”他人也觉得不错”。同行评审能发现作者自己的盲点，提升成果质量，同时也是一个双向学习的机会。

常见用法：

常见搭配： - conduct a peer review 进行同行评审 - submit for peer review 提交同行评审 - the review is constructive 评审有建设性

常用句型： - Peer review catches blind spots that the author cannot see. 同行评审能发现作者看不到的盲点。 - The best peer reviews are constructive, not judgmental. 最好的同行评审是建设性的，而非评判性的。

概念安置卡：

RU 名称：Peer Review

主位置：Work → Feedback → Peer Review

关联位置：
- Work → Project → Project Artifact
- Mind → Learning → Feedback Utilization

关联动作：conduct, submit, respond to, improve

关联属性：constructive, critical, thorough, superficial

说明：Peer Review 是同行检查单位。它帮助主体通过他者视角发现盲点并提升成果质量。

18.6 Practice 练习：Container 示例

18.6.1 Runtime Training 自动调用训练

Runtime Training 是将概念从”知道”推向”自动调用”的系统化练习。它不是学习新知识，而是让已有知识在需要时自动出现。

收纳 RU：spaced repetition、retrieval practice、contextual trigger、fluency drill

主体增益：它帮助主体区分”我学过”和”我能自动调用”。很多知识停留在被动记忆层面，通过 Runtime Training 可以将其转化为即时可用的判断工具。

常见用法：

常见搭配： - train for runtime 训练自动调用 - the concept is not yet in runtime 概念尚未进入自动调用 - runtime training takes repetition 自动调用训练需要重复

常用句型： - I need runtime training for this concept, not just reading. 这个概念我需要自动调用训练，不只是阅读。 - Runtime training turns knowledge into instinct. 自动调用训练将知识转化为直觉。

概念安置卡：

RU 名称：Runtime Training

主位置：Work → Practice → Runtime Training

关联位置：
- Mind → Cognition → Runtime
- Mind → Learning → Deliberate Practice

关联动作：practice, automate, trigger, internalize

关联属性：effective, inconsistent, ongoing, complete

说明：Runtime Training 是自动调用训练单位。它帮助主体将被动知识转化为即时可用的判断工具。

18.6.2 Skill Drill 技能训练

Skill Drill 是针对单一技能的重复性训练。它不是完整项目，而是刻意练习中的具体动作。

收纳 RU：typing drill、writing drill、coding exercise、speaking practice

主体增益：它帮助主体区分”我在做项目”和”我在练基础技能”。很多时候项目进展慢不是因为项目难，而是因为基础技能不够熟练。Skill Drill 补足基础。

常见用法：

常见搭配： - do a skill drill 做技能训练 - practice daily 每天练习 - the drill targets a weak point 训练针对弱点

常用句型： - I need to practice this skill before applying it to the project. 我需要先练习这个技能再应用到项目中。 - Skill drills feel boring but they build the foundation. 技能训练感觉枯燥，但它们在打基础。

概念安置卡：

RU 名称：Skill Drill

主位置：Work → Practice → Skill Drill

关联位置：
- Mind → Learning → Deliberate Practice
- Work → Task → Single Action Task

关联动作：practice, repeat, measure, improve

关联属性：targeted, scattered, effective, mindless

说明：Skill Drill 是单一技能训练单位。它帮助主体补足基础能力，为复杂项目做准备。

18.6.3 Feedback Loop 反馈循环

Feedback Loop 是行动-反馈-修正的循环机制。它不是单次反馈，而是持续迭代的系统。

收纳 RU：iteration cycle、review cycle、test-feedback-adjust、continuous improvement

主体增益：它帮助主体从”我做完了”转向”我根据反馈改进了什么”。没有反馈循环的练习只是重复，不会带来进步。

常见用法：

常见搭配： - close the feedback loop 闭合反馈循环 - the feedback loop is too slow 反馈循环太慢 - shorten the feedback loop 缩短反馈循环

常用句型： - I need a faster feedback loop to improve this skill. 我需要更快的反馈循环来提升这个技能。 - Short feedback loops accelerate learning. 短反馈循环加速学习。

概念安置卡：

RU 名称：Feedback Loop

主位置：Work → Practice → Feedback Loop

关联位置：
- Mind → Learning → Feedback Utilization
- Work → Feedback → Error Feedback

关联动作：establish, shorten, close, maintain

关联属性：fast, slow, effective, broken

说明：Feedback Loop 是迭代改进单位。它帮助主体建立行动-反馈-修正的持续循环。

18.7 Task 任务：Container 示例

18.7.1 Single Action Task 单步任务

Single Action Task 是可以在一次连续行动中完成的任务。它不需要拆分，不需要等待，不需要多步协调。

收纳 RU：send email、make call、submit form、sign document

主体增益：它帮助主体区分”这是一个任务”和”这是一个项目”。把单步任务当成项目来管理会浪费精力，把项目当成单步任务会永远完不成。

常见用法：

常见搭配： - complete a single action task 完成单步任务 - batch single action tasks 批量处理单步任务 - the task takes less than 5 minutes 任务不到 5 分钟

常用句型： - This is a single action task, I should just do it now. 这是一个单步任务，我应该现在就做。 - I batch all single action tasks under 5 minutes. 我把所有 5 分钟以下的单步任务批量处理。

概念安置卡：

RU 名称：Single Action Task

主位置：Work → Task → Single Action Task

关联位置：
- Work → Plan → Step
- Work → Goal → Process Goal

关联动作：complete, delegate, batch, defer

关联属性：quick, complex, urgent, routine

说明：Single Action Task 是一次性行动单位。它帮助主体识别并快速处理不需要拆分的简单任务。

18.7.2 Recurring Task 重复任务

Recurring Task 是定期出现的任务。它不是项目，而是维护性工作——周报、月度审查、定期备份。

收纳 RU：weekly review、daily standup、monthly report、regular backup

主体增益：它帮助主体区分”一次性任务”和”需要系统化处理的任务”。重复任务如果每次都从头处理，会消耗大量决策精力。建立模板和流程可以大幅降低重复任务的成本。

常见用法：

常见搭配： - automate a recurring task 自动化重复任务 - the task recurs weekly 任务每周重复 - create a template for the task 为任务创建模板

常用句型： - This recurring task needs a template. 这个重复任务需要一个模板。 - I automated my weekly report to save time. 我自动化了周报来节省时间。

概念安置卡：

RU 名称：Recurring Task

主位置：Work → Task → Recurring Task

关联位置：
- Work → Method → Framework
- Technology → Automation → Pipeline

关联动作：automate, template, schedule, eliminate

关联属性：frequent, infrequent, automatable, manual

说明：Recurring Task 是周期性任务单位。它帮助主体将重复性工作系统化为模板或流程。

18.7.3 Subtask 子任务

Subtask 是从一个较大任务中拆分出来的较小单元。它比 Step 更完整——一个 Subtask 本身就是一个可交付的工作单元，而不是单纯的动作步骤。

收纳 RU：child task、task breakdown、component task、work unit

主体增益：它帮助主体区分”这个任务太大”和”这个任务可以拆成子任务”。不会拆分子任务的人会被大任务压垮，善于拆分的人能持续获得完成感。

常见用法：

常见搭配： - break down into subtasks 拆分为子任务 - complete a subtask 完成子任务 - the subtask is still too large 子任务仍然太大

常用句型： - This task needs to be broken down into smaller subtasks. 这个任务需要拆分为更小的子任务。 - Each subtask should be completable in one session. 每个子任务应该能在一次工作时段内完成。

概念安置卡：

RU 名称：Subtask

主位置：Work → Task → Subtask

关联位置：
- Work → Plan → Step
- Work → Project → Milestone

关联动作：break down, complete, delegate, merge

关联属性：small, large, independent, dependent

说明：Subtask 是任务拆分单位。它帮助主体将大任务分解为可管理的独立工作单元。

18.8 Project 项目：Container 示例

18.8.1 Project Artifact 项目产物

Project Artifact 是项目过程中产生的具体成果——文档、代码、设计稿、报告。它是项目价值的可见载体。

收纳 RU：deliverable、prototype、specification、report、codebase

主体增益：它帮助主体区分”我在忙”和”我在产出”。项目不是活动清单，而是产出一系列 artifact 的过程。关注 artifact 而非活动，能更清晰地判断项目进度。

常见用法：

常见搭配： - produce an artifact 产出一个产物 - review the artifact 审查产物 - the artifact is incomplete 产物不完整

常用句型： - What artifact should this meeting produce? 这个会议应该产出什么产物？ - A project without clear artifacts is just activity. 没有清晰产物的项目只是活动。

概念安置卡：

RU 名称：Project Artifact

主位置：Work → Project → Project Artifact

关联位置：
- Language → Text → Document
- Work → Feedback → Error Feedback

关联动作：produce, review, deliver, archive

关联属性：complete, draft, final, deprecated

说明：Project Artifact 是项目成果单位。它帮助主体关注可交付的产出而非单纯的活动。

18.8.2 Milestone 里程碑

Milestone 是项目中的关键检查点。它不是日常进度，而是标志阶段性完成的节点。

收纳 RU：phase completion、checkpoint、gate review、release point

主体增益：它帮助主体从”项目进行中”转向”项目到了哪个阶段”。没有里程碑的项目容易失去方向感和动力。

常见用法：

常见搭配： - reach a milestone 达到里程碑 - miss a milestone 错过里程碑 - set a milestone 设定里程碑

常用句型： - We reached the first milestone ahead of schedule. 我们提前达到了第一个里程碑。 - A milestone is not a deadline, it is a checkpoint. 里程碑不是截止日期，而是检查点。

概念安置卡：

RU 名称：Milestone

主位置：Work → Project → Milestone

关联位置：
- Work → Goal → Process Goal
- Work → Feedback → Error Feedback

关联动作：set, reach, miss, celebrate

关联属性：critical, optional, achieved, missed

说明：Milestone 是项目阶段检查点单位。它帮助主体判断项目进度并维持动力。

18.9 Problem 问题：Container 示例

18.9.1 Root Problem 根问题

Root Problem 是导致一系列表面问题的核心问题。它不是”这个问题好麻烦”，而是”所有这些问题都指向同一个根问题”。

收纳 RU：core issue、systemic problem、underlying cause、fundamental challenge

主体增益：它帮助主体区分”我在处理症状”和”我在处理根问题”。解决根问题后，多个表面问题会同时消失。识别根问题是高效解决问题的前提。

常见用法：

常见搭配： - identify the root problem 识别根问题 - address the root problem 处理根问题 - the root problem is unclear 根问题不清晰

常用句型： - All these symptoms point to one root problem. 所有这些症状都指向一个根问题。 - Fixing symptoms without addressing the root problem is temporary. 不处理根问题只修复症状只是暂时的。

概念安置卡：

RU 名称：Root Problem

主位置：Work → Problem → Root Problem

关联位置：
- Language → Question → Diagnostic Question
- Mind → Cognition → Cognitive Bias

关联动作：identify, trace, address, verify

关联属性：clear, hidden, systemic, isolated

说明：Root Problem 是核心问题单位。它帮助主体识别导致一系列表面问题的根本原因。

18.9.2 Problem Statement 问题陈述

Problem Statement 是对问题的精确描述。它不是抱怨，而是结构化的问题定义。

收纳 RU：problem definition、issue description、current state vs desired state、gap analysis

主体增益：它帮助主体从”这有问题”转向”问题具体是什么”。好的问题陈述已经包含了 50% 的解决方案。

常见用法：

常见搭配： - write a problem statement 写问题陈述 - refine the problem statement 精炼问题陈述 - the problem statement is too vague 问题陈述太模糊

常用句型： - Before solving, I need a clear problem statement. 在解决之前，我需要一个清晰的问题陈述。 - A good problem statement includes the current state, desired state, and the gap. 好的问题陈述包含当前状态、期望状态和差距。

概念安置卡：

RU 名称：Problem Statement

主位置：Work → Problem → Problem Statement

关联位置：
- Language → Sentence → Statement
- Work → Problem → Root Problem

关联动作：write, refine, validate, share

关联属性：clear, vague, actionable, abstract

说明：Problem Statement 是问题定义单位。它帮助主体将模糊困扰转化为结构化的问题描述。
