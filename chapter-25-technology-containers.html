27  第 25 章：Technology 的 Container 示例（Technology Containers）

27.1 本章要解决的问题

第 24 章梳理了 Technology 技术单位下的 8 个 Group。本章继续向下一层推进，展示每个 Group 下可以放置哪些 Container。

Technology 是个人能力的扩展器。大模型时代，每个人都在与技术系统交互。理解技术的 RU 结构，意味着你能选择工具、评估模型、设计工作流，而不只是被动使用。

27.2 Tool 工具：Container 示例

27.2.1 Cognitive Tool 认知工具

Cognitive Tool 是扩展思考能力的工具。它不是”记录”工具，是”帮助思考”的工具——知识库、思维导图、笔记系统。

收纳 RU：knowledge base、mind map、note-taking system、outliner

主体增益：Cognitive Tool 帮助主体区分”存文件的工具”和”帮我想的工具”。一个好认知工具不只是存储信息，它帮助发现连接和产生新理解。

常见用法：

常见搭配： - use a cognitive tool 使用认知工具 - choose the right tool 选择合适的工具 - the tool shapes how you think 工具塑造你的思考方式

常用句型： - A good cognitive tool extends your thinking, not just your memory. 一个好的认知工具扩展的是思考能力，不只是记忆能力。 - The tool should fit your thinking style, not the other way around. 工具应该匹配你的思考风格，而不是反过来。

概念安置卡：

RU 名称：Cognitive Tool

主位置：Technology → Tool → Cognitive Tool

关联位置：
- Mind → Memory → Working Memory

关联动作：select, use, master, replace

关联属性：generative, organizing, externalizing

说明：Cognitive Tool 是思维扩展工具单位。它帮助主体选择真正扩展思考能力而非仅存储信息的工具。

27.2.2 Productivity Tool 效率工具

Productivity Tool 是帮助主体更快完成任务的工具。它不是扩展思考，而是加速执行——任务管理、日历、自动化工具。

收纳 RU：task manager、calendar、todo list、timer、project management tool

主体增益：它帮助主体区分”我需要帮我想的工具”和”我需要帮我做的工具”。效率工具的核心价值不是功能多，而是减少从意图到行动的时间。

常见用法：

常见搭配： - use a productivity tool 使用效率工具 - the tool reduces friction 工具减少操作阻力 - switch to a better tool 切换到更好的工具

常用句型： - A good productivity tool reduces the time between intention and action. 好的效率工具缩短从意图到行动的时间。 - The best productivity tool is the one you actually use. 最好的效率工具是你真正在用的那个。

概念安置卡：

RU 名称：Productivity Tool

主位置：Technology → Tool → Productivity Tool

关联位置：
- Work → Task → Single Action Task
- Technology → Automation → Pipeline

关联动作：use, evaluate, switch, master

关联属性：fast, slow, simple, complex

说明：Productivity Tool 是执行加速单位。它帮助主体选择能减少从意图到行动时间的工具。

27.2.3 Creative Tool 创作工具

Creative Tool 是帮助主体生成新内容的工具。它不是管理已有信息，而是创造新事物——设计软件、视频编辑器、音乐制作工具、写作平台。

收纳 RU：design tool、video editor、music production software、writing platform

主体增益：它帮助主体区分”我在消费”和”我在创造”。创作工具降低创造的门槛，让主体从被动的消费者转变为主动的创造者。工具的选择直接影响创作的质量和效率。

常见用法：

常见搭配： - master a creative tool 掌握创作工具 - the tool enables new forms of expression 工具开启新的表达方式 - creative tool literacy 创作工具素养

常用句型： - A good creative tool lowers the barrier between idea and output. 好的创作工具降低了从想法到产出的门槛。 - The tool shapes what you can create, so choose it intentionally. 工具塑造你能创造什么，所以要慎重选择。

概念安置卡：

RU 名称：Creative Tool

主位置：Technology → Tool → Creative Tool

关联位置：
- Language → Text → Article
- Work → Project → Project Artifact

关联动作：learn, master, use, combine

关联属性：expressive, limiting, beginner-friendly, professional

说明：Creative Tool 是内容生成单位。它帮助主体从被动消费转向主动创造。

27.3 AI Model AI 模型：Container 示例

27.3.1 Language Model 语言模型

Language Model 是处理文本的 AI 系统。它不只是聊天机器人，而是理解、生成和处理语言的能力单元。

收纳 RU：GPT、Claude、Gemini、embedding model

主体增益：Language Model 帮助主体理解 AI 的能力边界——它能做什么、不能做什么。了解模型的能力范围后，主体能设计更有效的使用策略。

常见用法：

常见搭配： - prompt a language model 向语言模型发指令 - evaluate model output 评估模型输出 - the model’s capability 模型的能力范围

常用句型： - This language model is good at summarization but weak at reasoning. 这个语言模型擅长摘要但不擅长推理。 - Understanding the model’s capability helps me design better prompts. 了解模型的能力范围帮助我设计更好的提示词。

概念安置卡：

RU 名称：Language Model

主位置：Technology → AI Model → Language Model

关联位置：
- Language → Instruction → Prompt

关联动作：prompt, evaluate, integrate, fine-tune

关联属性：capable, limited, general, specialized

说明：Language Model 是文本 AI 单位。它帮助主体理解和使用大语言模型的能力与边界。

27.3.2 Image Model 图像模型

Image Model 是处理图像的 AI 系统。它能生成、编辑、识别和分析视觉内容——从照片到设计稿。

收纳 RU：Stable Diffusion、DALL-E、Midjourney、image recognition model

主体增益：它帮助主体理解”视觉 AI 能做什么”。无论是生成配图、处理照片还是分析视觉数据，了解图像模型的能力边界让主体能在更多场景中使用视觉 AI。

常见用法：

常见搭配： - generate an image 生成图像 - edit with AI 用 AI 编辑 - the model handles style transfer 模型处理风格迁移

常用句型： - Image models can generate visuals from text descriptions. 图像模型可以根据文字描述生成视觉内容。 - Understanding image models helps me integrate visual AI into my workflow. 了解图像模型帮助我将视觉 AI 集成到工作流中。

概念安置卡：

RU 名称：Image Model

主位置：Technology → AI Model → Image Model

关联位置：
- Technology → Tool → Creative Tool
- Language → Instruction → Prompt

关联动作：generate, edit, analyze, integrate

关联属性：photorealistic, stylized, accurate, hallucinated

说明：Image Model 是视觉 AI 单位。它帮助主体理解和使用图像生成与处理 AI。

27.3.3 Embedding Model 嵌入模型

Embedding Model 将文本、图像或其他数据转换为向量表示。它不直接生成内容，而是让机器理解内容之间的语义关系。

收纳 RU：text embedding、vector representation、semantic search、RAG

主体增益：它帮助主体理解”AI 如何理解语义相似性”。嵌入是实现语义搜索、推荐系统和 RAG 的核心技术。理解嵌入模型能让主体更有效地使用这些系统。

常见用法：

常见搭配： - use an embedding model 使用嵌入模型 - generate embeddings 生成向量嵌入 - embeddings capture semantic meaning 嵌入捕捉语义

常用句型： - Embedding models convert text into vectors that capture meaning. 嵌入模型将文本转换为捕捉语义的向量。 - Understanding embeddings helps me build better search and recommendation systems. 理解嵌入帮助我构建更好的搜索和推荐系统。

概念安置卡：

RU 名称：Embedding Model

主位置：Technology → AI Model → Embedding Model

关联位置：
- Technology → Data → Dataset
- Technology → System → Backend System

关联动作：use, fine-tune, compare, evaluate

关联属性：semantic, sparse, dense, contextual

说明：Embedding Model 是语义向量单位。它帮助主体理解 AI 系统如何表示和比较语义关系。

27.4 Workflow 工作流：Container 示例

27.4.1 AI Workflow AI 工作流

AI Workflow 是以 AI 为核心的端到端流程设计。它不是”问 AI 一个问题”，而是设计包含多步 AI 调用的处理流程。

收纳 RU：AI writing workflow、AI research workflow、AI code generation workflow

主体增益：AI Workflow 帮助主体从”用 AI 回答单个问题”升级到”用 AI 完成一个完整的任务流程”。前者是工具使用，后者是系统设计。

常见用法：

常见搭配： - design an AI workflow 设计 AI 工作流 - automate with AI 用 AI 自动化 - the workflow includes multiple AI calls 工作流包含多次 AI 调用

常用句型： - An AI workflow can automate a multi-step research task. AI 工作流可以自动化多步研究任务。 - Designing a good AI workflow requires understanding both the task and the model. 设计好的 AI 工作流需要同时理解任务和模型。

概念安置卡：

RU 名称：AI Workflow

主位置：Technology → Workflow → AI Workflow

关联位置：
- Technology → AI Model → Language Model
- Work → Method → Framework

关联动作：design, automate, iterate, hand off

关联属性：supervised, autonomous, simple, multi-step

说明：AI Workflow 是智能流程单位。它帮助主体从单次 AI 使用升级到多步流程设计。

27.4.2 Manual Workflow 手动工作流

Manual Workflow 是由人执行每一步的流程。它不是自动化，而是人为操作的标准化序列——检查清单、标准操作流程、手动数据录入。

收纳 RU：checklist、standard operating procedure、manual review、step-by-step guide

主体增益：它帮助主体区分”这个应该自动化”和”这个目前还需要手动做”。不是所有流程都值得自动化。理解手动工作流的价值在于识别哪些流程需要标准化，以及哪些是自动化的候选。

常见用法：

常见搭配： - follow a manual workflow 遵循手动工作流 - document the manual workflow 记录手动工作流 - the workflow is still manual 工作流仍是手动的

常用句型： - This manual workflow needs to be documented before it can be automated. 这个手动工作流在自动化之前需要先被文档化。 - Manual workflows are reliable when well-documented. 手动工作流在文档化良好时是可靠的。

概念安置卡：

RU 名称：Manual Workflow

主位置：Technology → Workflow → Manual Workflow

关联位置：
- Work → Method → Framework
- Technology → Automation → Pipeline

关联动作：follow, document, optimize, automate

关联属性：documented, ad-hoc, reliable, error-prone

说明：Manual Workflow 是手动流程单位。它帮助主体标准化重复性人工操作，并为自动化做准备。

27.4.3 Hybrid Workflow 混合工作流

Hybrid Workflow 是人机协作的流程。它不是纯粹的人工或自动，而是两者结合——AI 生成初稿、人审核修改；人做决策、AI 提供建议。

收纳 RU：human-in-the-loop、AI-assisted workflow、human-AI collaboration、augmented workflow

主体增益：它帮助主体设计”人和 AI 各自做什么”的分工。好的混合工作流让 AI 处理它擅长的（速度、规模），让人处理人擅长的（判断、创造、责任）。

常见用法：

常见搭配： - design a hybrid workflow 设计混合工作流 - the workflow has a human-in-the-loop 工作流有人工介入 - balance human and AI tasks 平衡人和 AI 的任务

常用句型： - In a hybrid workflow, AI handles the rote work and humans handle the judgment calls. 在混合工作流中，AI 处理重复性工作，人处理判断性工作。 - The key to a good hybrid workflow is knowing what to give to AI and what to keep. 好的混合工作流的关键是知道什么交给 AI、什么自己保留。

概念安置卡：

RU 名称：Hybrid Workflow

主位置：Technology → Workflow → Hybrid Workflow

关联位置：
- Technology → AI Model → Language Model
- Work → Method → Framework

关联动作：design, iterate, hand off, balance

关联属性：human-led, AI-led, balanced, unbalanced

说明：Hybrid Workflow 是人机协作单位。它帮助主体设计最优的人和 AI 任务分工。

27.5 Software 软件：Container 示例

27.5.1 Application 应用

Application 是完成特定任务的软件程序。它不是操作系统，而是面向用户的功能性工具——编辑器、浏览器、通讯工具。

收纳 RU：editor、browser、messaging app、productivity tool、design tool

主体增益：它帮助主体区分”我需要一个工具”和”我需要一个什么样的工具”。选择合适的应用能大幅提升工作效率，而不合适的工具会成为瓶颈。

常见用法：

常见搭配： - use an application 使用应用 - switch applications 切换应用 - the app is intuitive 应用直观易用

常用句型： - I need an application that supports my workflow. 我需要一个支持我工作流的应用。 - The right application can save hours of work. 合适的应用能节省数小时工作。

概念安置卡：

RU 名称：Application

主位置：Technology → Software → Application

关联位置：
- Work → Method → Framework
- Technology → Tool → Cognitive Tool

关联动作：select, use, master, replace

关联属性：intuitive, complex, reliable, buggy

说明：Application 是功能性软件单位。它帮助主体选择并使用适合工作需求的软件工具。

27.5.2 UI Component / Widget 界面组件

UI Component / Widget 是软件界面的基本构建块。它是用户与软件交互的直接触点——按钮、输入框、列表、弹窗。

收纳 RU：button、input、table、modal、dropdown、card

主体增益：它帮助主体理解”软件界面是如何组织的”。了解 UI 组件后，主体能更有效地使用软件、描述问题，甚至与 AI 协作生成界面。

常见用法：

常见搭配： - interact with a UI component 与界面组件交互 - the component is responsive 组件响应式 - customize the widget 自定义组件

常用句型： - This UI component is not intuitive. 这个界面组件不直观。 - Understanding UI components helps me describe what I need. 了解界面组件帮助我描述我的需求。

概念安置卡：

RU 名称：UI Component / Widget

主位置：Technology → Software → UI Component / Widget

关联位置：
- Technology → Software → Application
- Language → Instruction → Prompt

关联动作：click, interact, customize, report

关联属性：responsive, broken, intuitive, confusing

说明：UI Component / Widget 是界面交互单位。它帮助主体理解并使用软件界面的基本构建块。

27.6 Data 数据：Container 示例

27.6.1 Dataset 数据集

Dataset 是结构化数据的集合。它不是原始信息，而是有组织、可查询、可分析的数据单元。

收纳 RU：training data、survey data、log data、benchmark dataset

主体增益：它帮助主体理解”数据是如何被组织和使用”。在大模型时代，理解数据集的性质是评估 AI 输出质量的基础。

常见用法：

常见搭配： - collect a dataset 收集数据集 - the dataset is biased 数据集有偏误 - train on a dataset 在数据集上训练

常用句型： - The quality of the dataset determines the quality of the analysis. 数据集的质量决定分析的质量。 - I need to understand the dataset before drawing conclusions. 在得出结论之前，我需要了解数据集。

概念安置卡：

RU 名称：Dataset

主位置：Technology → Data → Dataset

关联位置：
- Technology → AI Model → Language Model
- Work → Feedback → Error Feedback

关联动作：collect, clean, analyze, share

关联属性：large, small, clean, biased

说明：Dataset 是结构化数据单位。它帮助主体理解数据的组织方式及其对分析结果的影响。

27.6.2 Data Structure 数据结构

Data Structure 是数据在计算机中的组织方式。它不是数据本身，而是数据存放的形态——列表、树、表格、图。

收纳 RU：array、tree、table、graph、hash map、queue

主体增益：它帮助主体理解”数据是怎么被组织和访问的”。不同的数据结构适合不同的问题场景。了解基本数据结构后，主体能更好地理解软件为什么快或慢、为什么某个查询方式更高效。

常见用法：

常见搭配： - choose a data structure 选择数据结构 - the data structure is efficient 数据结构高效 - organize data in a tree structure 以树结构组织数据

常用句型： - The right data structure makes operations fast. 合适的数据结构让操作变快。 - Understanding data structures helps me design better systems. 了解数据结构帮助我设计更好的系统。

概念安置卡：

RU 名称：Data Structure

主位置：Technology → Data → Data Structure

关联位置：
- Technology → System → Backend System
- Technology → Software → Application

关联动作：choose, implement, optimize, understand

关联属性：linear, hierarchical, relational, flat

说明：Data Structure 是数据组织形态单位。它帮助主体理解数据在系统中的存储和访问方式。

27.6.3 Data Pipeline 数据管道

Data Pipeline 是将数据从源端移动到目标端并在此过程中进行转换的自动化流程。它不是单次数据迁移，而是持续的数据处理流。

收纳 RU：ETL、data ingestion、data transformation、data streaming、data warehousing

主体增益：它帮助主体理解”数据是如何流动和转换的”。在 AI 时代，数据管道的质量直接决定了模型的质量。了解数据管道的概念帮助主体设计更可靠的数据系统。

常见用法：

常见搭配： - build a data pipeline 建立数据管道 - the pipeline ingests data 管道摄入数据 - monitor the data pipeline 监控数据管道

常用句型： - A data pipeline moves and transforms data from source to destination. 数据管道将数据从源端移动到目标端并进行转换。 - The quality of the data pipeline determines the quality of the analysis. 数据管道的质量决定分析的质量。

概念安置卡：

RU 名称：Data Pipeline

主位置：Technology → Data → Data Pipeline

关联位置：
- Technology → Automation → Pipeline
- Technology → System → Backend System

关联动作：build, monitor, debug, optimize

关联属性：real-time, batch, reliable, fragile

说明：Data Pipeline 是数据流单位。它帮助主体理解数据如何被收集、转换和传输。

27.7 System 系统：Container 示例

27.7.1 Backend System 后端系统

Backend System 是支撑应用运行的基础设施。用户看不到它，但它决定了系统的性能、可靠性和扩展性。

收纳 RU：server、database、API、cache、load balancer

主体增益：它帮助主体理解”应用背后发生了什么”。不需要成为工程师，但理解后端系统的基本概念能帮助主体更好地评估技术方案的可行性。

常见用法：

常见搭配： - the backend system is slow 后端系统慢 - scale the backend system 扩展后端系统 - backend system failure 后端系统故障

常用句型： - The backend system determines how fast the app responds. 后端系统决定应用的响应速度。 - Understanding the backend helps me set realistic expectations. 了解后端帮助我设定合理的期望。

概念安置卡：

RU 名称：Backend System

主位置：Technology → System → Backend System

关联位置：
- Technology → Data → Dataset
- Work → Project → Project Artifact

关联动作：deploy, scale, monitor, debug

关联属性：fast, slow, reliable, unstable

说明：Backend System 是基础设施单位。它帮助主体理解应用背后的技术架构和性能限制。

27.7.2 Frontend 前端

Frontend 是用户直接看到和交互的系统层。它不是应用的全部，而是用户能感知到的部分——界面、交互、视觉、响应。

收纳 RU：user interface、client-side、web page、mobile UI、responsive design

主体增益：它帮助主体区分”我看到的界面”和”支撑界面的系统”。前端是用户对应用的第一印象——速度快、布局好、交互顺滑的前端让用户觉得”这个软件好用”。理解前端的限制能帮助主体设定合理期望。

常见用法：

常见搭配： - build the frontend 构建前端 - the frontend is responsive 前端是响应式的 - optimize frontend performance 优化前端性能

常用句型： - The frontend determines what the user sees and how they interact. 前端决定用户看到什么以及如何交互。 - A fast backend with a slow frontend still feels like a slow app. 后端再快，前端慢还是会让人觉得应用慢。

概念安置卡：

RU 名称：Frontend

主位置：Technology → System → Frontend

关联位置：
- Technology → Software → UI Component / Widget
- Technology → Software → Application

关联动作：build, design, optimize, test

关联属性：fast, slow, intuitive, confusing

说明：Frontend 是用户交互层单位。它帮助主体理解应用的可见部分及其对用户体验的影响。

27.7.3 API 接口

API 是系统之间通信的约定接口。它不是用户界面，而是程序之间的对话协议——一个系统请求数据或功能，另一个系统响应。

收纳 RU：REST API、GraphQL、webhook、endpoint、request-response

主体增益：它帮助主体理解”系统之间如何对话”。API 是现代软件集成的核心。理解 API 的基本概念后，主体能更好地连接不同工具、自动化流程、或评估系统集成的复杂度。

常见用法：

常见搭配： - call an API 调用接口 - design an API 设计接口 - the API is well-documented 接口文档良好

常用句型： - APIs allow different software systems to communicate with each other. 接口让不同的软件系统互相通信。 - Understanding APIs helps me integrate tools and automate workflows. 了解 API 帮助我集成工具和自动化工作流。

概念安置卡：

RU 名称：API

主位置：Technology → System → API

关联位置：
- Technology → Automation → Pipeline
- Technology → Technology Platform → Cloud Platform

关联动作：call, design, document, integrate

关联属性：fast, slow, well-documented, poorly-documented

说明：API 是系统通信接口单位。它帮助主体理解并利用系统间的集成能力。

27.8 Technology Platform 技术平台：Container 示例

27.8.1 Cloud Platform 云平台

Cloud Platform 是提供计算、存储和网络服务的在线基础设施。它不是本地服务器，而是按需使用的远程计算资源。

收纳 RU：AWS、GCP、Azure、serverless、cloud storage

主体增益：它帮助主体理解”现代技术基础设施如何运作”。即使不直接使用云平台，理解其基本概念能帮助主体评估技术方案的可行性和成本。

常见用法：

常见搭配： - deploy on a cloud platform 在云平台上部署 - cloud platform cost 云平台成本 - migrate to the cloud 迁移到云端

常用句型： - Cloud platforms make it easy to scale applications. 云平台让扩展应用变得容易。 - Understanding cloud costs helps me budget for projects. 了解云成本帮助我为项目做预算。

概念安置卡：

RU 名称：Cloud Platform

主位置：Technology → Technology Platform → Cloud Platform

关联位置：
- Technology → System → Backend System
- Value → Cost → Opportunity Cost

关联动作：deploy, scale, monitor, optimize

关联属性：scalable, expensive, reliable, complex

说明：Cloud Platform 是远程计算资源单位。它帮助主体理解现代技术基础设施的运作方式和成本结构。

27.8.2 API Platform 接口平台

API Platform 是提供 API 服务供其他应用调用的平台。它不是具体的 API，而是运营 API 的基础设施——API 市场、开发者门户、API 网关。

收纳 RU：API marketplace、developer portal、API gateway、Stripe API、Twilio

主体增益：它帮助主体理解”哪些服务可以通过 API 直接集成”。利用 API 平台可以大幅减少重复开发。与其自己实现支付、短信、地图等功能，不如集成现有的 API 平台。

常见用法：

常见搭配： - use an API platform 使用接口平台 - integrate with an API platform 集成接口平台 - the platform offers a rich API 平台提供丰富的接口

常用句型： - API platforms let you integrate complex services with minimal code. 接口平台让你用最少的代码集成复杂服务。 - Before building a feature, check if an API platform already offers it. 在开发一个功能之前，先检查是否有接口平台已经提供了它。

概念安置卡：

RU 名称：API Platform

主位置：Technology → Technology Platform → API Platform

关联位置：
- Technology → System → API
- Work → Project → Project Artifact

关联动作：integrate, evaluate, subscribe, deprecate

关联属性：well-documented, reliable, expensive, free

说明：API Platform 是 API 服务基础设施单位。它帮助主体利用现成 API 减少重复开发。

27.8.3 Dev Platform 开发平台

Dev Platform 是辅助软件开发的平台和工具集合。它不是单个工具，而是完整的开发环境——代码托管、CI/CD、包管理、协作工具。

收纳 RU：GitHub、GitLab、VS Code、npm、Docker、DevOps platform

主体增益：它帮助主体理解”现代开发是如何组织的”。好的开发平台让团队协作更高效、代码质量更可控、发布流程更可靠。即使不写代码，理解开发平台也能帮助主体管理技术项目。

常见用法：

常见搭配： - use a dev platform 使用开发平台 - the platform hosts the code 平台托管代码 - automate builds on the platform 在平台上自动化构建

常用句型： - Dev platforms provide the infrastructure for modern software development. 开发平台为现代软件开发提供基础设施。 - Choosing the right dev platform affects team productivity. 选择合适的开发平台影响团队生产力。

概念安置卡：

RU 名称：Dev Platform

主位置：Technology → Technology Platform → Dev Platform

关联位置：
- Technology → Automation → Pipeline
- Work → Project → Project Artifact

关联动作：use, configure, migrate, evaluate

关联属性：integrated, fragmented, beginner-friendly, enterprise

说明：Dev Platform 是开发基础设施单位。它帮助主体理解并选择支撑软件开发流程的平台和工具。

27.9 Automation 自动化：Container 示例

27.9.1 Pipeline 流水线

Pipeline 是自动化的多步处理流程。它不是单次脚本，而是可重复、可监控、可触发的工作流。

收纳 RU：CI/CD pipeline、data pipeline、build pipeline、deployment pipeline

主体增益：它帮助主体区分”我手动做这个”和”我把它自动化成流水线”。Pipeline 减少重复劳动，提高一致性和可追溯性。

常见用法：

常见搭配： - build a pipeline 建立流水线 - the pipeline failed 流水线失败 - automate the pipeline 自动化流水线

常用句型： - I need to build a pipeline for this recurring task. 我需要为这个重复任务建立流水线。 - A good pipeline runs without manual intervention. 好的流水线无需人工干预。

概念安置卡：

RU 名称：Pipeline

主位置：Technology → Automation → Pipeline

关联位置：
- Work → Task → Recurring Task
- Technology → Workflow → AI Workflow

关联动作：build, trigger, monitor, fix

关联属性：automated, manual, reliable, fragile

说明：Pipeline 是自动化流程单位。它帮助主体将重复性多步任务转化为可监控的自动流水线。

27.9.2 Script 脚本

Script 是执行单一自动化任务的小程序。它不是完整的流水线，而是完成一个具体功能的自动化片段——批量重命名文件、自动发送报告、定时备份。

收纳 RU：shell script、automation script、cron job、macro

主体增益：它帮助主体区分”这个重复动作可以写成脚本”。脚本是自动化的最小单位。学会写简单脚本可以节省大量手动操作时间。不需要是程序员也能用脚本把几秒的事变成自动执行。

常见用法：

常见搭配： - write a script 写脚本 - run a script 运行脚本 - automate with a script 用脚本自动化

常用句型： - A good script automates one task really well. 好的脚本把一件事自动化得很好。 - If you do something more than three times, write a script for it. 如果你做一件事超过三次，就为它写个脚本。

概念安置卡：

RU 名称：Script

主位置：Technology → Automation → Script

关联位置：
- Technology → Tool → Productivity Tool
- Work → Task → Recurring Task

关联动作：write, run, schedule, debug

关联属性：one-time, recurring, simple, complex

说明：Script 是自动化小程序单位。它帮助主体将重复性单一操作转化为自动执行。

27.9.3 Rule-based Automation 规则自动化

Rule-based Automation 是基于预设条件触发的自动化。它不是脚本的一次执行，而是”当 X 发生时自动做 Y”的持续规则。

收纳 RU：if-then rule、trigger、auto-responder、workflow trigger、zap

主体增益：它帮助主体区分”我需要手动触发”和”我可以设定规则让它自动发生”。规则自动化不需要编程——IFTTT、Zapier、邮件过滤器都是规则自动化的例子。

常见用法：

常见搭配： - set up a rule-based automation 设置规则自动化 - the automation triggers when conditions are met 条件满足时自动化触发 - define the trigger condition 定义触发条件

常用句型： - Rule-based automation runs when specific conditions are met. 规则自动化在特定条件满足时自动运行。 - Setting up rules takes time upfront but saves time every day. 设置规则需要前期投入，但每天都能节省时间。

概念安置卡：

RU 名称：Rule-based Automation

主位置：Technology → Automation → Rule-based Automation

关联位置：
- Technology → Workflow → Hybrid Workflow
- Work → Task → Recurring Task

关联动作：set up, trigger, monitor, refine

关联属性：event-driven, time-based, reliable, fragile

说明：Rule-based Automation 是触发式自动化单位。它帮助主体将条件式重复操作转化为自动执行。
