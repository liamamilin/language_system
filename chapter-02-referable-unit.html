4  第 2 章：RU — Referable Unit，可指称单位（RU）

4.1 本章要解决的问题

从小学起你被教过词性：名词、动词、形容词、副词。这套分类在语法分析中有效，但它不能回答一个更关键的问题：哪些词值得被当作”一个东西”来安置、调用和训练？

你关心”efficient”和”efficiency”是不同词性。但在 RU 树里，efficiency 是 RU，efficient 不是。为什么？不是语法原因，是安置原因。

本章要建立 RU 的判断标准。读完这一章，你将拥有一个精确的工具来识别：一个语言单位是否值得放进你的 RU 树。

4.2 本章位置

RU 是本书的绝对主线。主体增益原则是筛选标准（什么值得进），RU 判断标准是分类工具（什么算一个单位）。第 3 章的四层结构是 RU 的安置层级。三者连续，不能跳过。

4.3 核心定义

RU 是 Referable Unit（可指称单位）的简称。定义如下：

RU 是语言中可以被当作一个”东西”来指称、讨论、分类、安置、连接和调用的语义单位。

拆解这个定义的每一部分：

可以被当作一个”东西”——你能用”这个”“那个”“它”来指称它。你在对话中可以说”这个 workflow 有问题”“那个 goal 需要调整”。

指称——你能用一个名称来识别它。workflow、attention、risk、feedback 都是名称。build、quickly、however 不是——它们指动作、程度或关系，但不是可以被指称的”东西”。

讨论——你能把它作为话题。“我们来谈谈 feedback 机制”——feedback 是讨论对象。

分类——你能问”这个 RU 属于哪一类？“——它应该有一个上层容器。

安置——你能在 RU 树中给它找一个位置。

连接——你能把不同 RU 连起来。“feedback 影响 attention，attention 影响 learning”。

调用——你在适当的场景能主动想到它，用它来理解或行动。

4.4 RU 的五个判断标准

判断一个单位是不是 RU，用五个问题：

4.4.1 标准一：可指称

你能用指示词指向它吗？

  • workflow → 是的。“这个 workflow 需要简化。”
  • anxiety → 是的。“这种 anxiety 让我做不了决定。”
  • build → 不一定。你可以说”这个建筑”，但”这个 build”很奇怪。作为名词时（“latest build of the software”）勉强可指称，但一般用法中它被指称的是 building 或 construction，不是 build 本身。

4.4.2 标准二：可分类

你能说出它属于什么上层类别吗？

  • attention → Mind → Attention
  • prompt → Language → Instruction → Prompt
  • friendship → Relationship → Connection → Bond

如果一个单位无法归入任何上层类别，它要么不是 RU，要么你的树还没长到它能放的位置。

4.4.3 标准三：可容纳

它能装下更具体的实例吗？或者它能被装进某个容器？

  • attention 能被装进 Mind → Attention 容器
  • distraction 是 attention 的一种具体表现，可以被装进 Mind → Attention 下的一个容器（如 Distraction）
  • 反过来，button 可以被装进 Technology → Software → UI Component

RU 不是孤立点。它要么是容器，要么被装进容器。

4.4.4 标准四：可连接

它能与其他 RU 建立有意义的关系吗？

  • goal + plan + action + feedback → 这是做事循环
  • attention + learning + memory → 这是学习链条
  • risk + cost + benefit → 这是决策结构

如果一个概念与其他概念没有任何有意义的连接，它要么过于孤立，要么不是核心 RU。

4.4.5 标准五：服务主体增益

这与第 1 章的标准相同。通过前四个标准只是一个语义单位。通过第五个标准才值得进入你的 RU 树。

4.5 RU 与词性的区别

这是本书最重要的区分之一。

词性分类回答：这个词在句子中充当什么语法成分？

RU 分类回答：这个语义单位在我的个人系统中充当什么概念角色？

区别 词性 RU
分类依据 语法功能 语义角色
关注点 词在句中的位置 概念在体系中的位置
处理对象 所有词汇 通过主体增益筛选的单位
对动词/形容词处理 需要分类 不作为主线，只作关联语言
目的 语法分析 概念安置与调用

举例：

efficient（形容词）vs efficiency（名词）

efficient 描述一种属性。你可以说”这个流程很 efficient”。但你不能把 efficient 当作一个东西来安置。你不能说”这个 efficient 是什么——它是高效的属性”。它是属性，不是实体。

efficiency 是 RU。你可以说”流程的 efficiency 需要优化”——efficiency 被当作一个可以被评估和优化的事物。

build（动词）vs project（名词）

build 是一个动作。你可以 build 一个 product，但 build 本身不是一个可以被安置的东西。project 是 RU，你可以讨论它的 scope、timeline、goal。

quickly（副词）vs speed（名词）

quickly 是方式。speed 可以是一种 RU（Value → Cost → Time Cost，或 Body → Movement → Speed）。

but（连词）vs tradeoff（名词）

but 是连接关系。tradeoff 是 RU——你可以分析一个 tradeoff，评估它，管理它。

RU 判断的简单检查：你能不能对这个人说一句”这个 X 需要处理”？

  • “这个 efficiency 需要提升” → 可以 → RU
  • “这个 efficient 需要提升” → 不可以 → 非 RU
  • “这个 project 需要处理” → 可以 → RU
  • “这个 build 需要处理” → 在特定语境（如软件构建产物）可以，一般情况不可以

4.6 动词、形容词、副词为什么不进入主线

这不是语言学决定，是系统效率决定。

RU 树是一个安置系统。它的结构主要由”可以被指称、分类和连接的语义单位”构成。动词、形容词、副词在 RU 树中扮演不同的角色：

动词关联：当一个 RU 被使用时，动词描述你对它做什么。

  • manage attention（管理注意力）
  • set a goal（设定目标）
  • assess risk（评估风险）

动词是操作，不是被操作的对象。

形容词关联：当一个 RU 被评估时，形容词描述它的状态。

  • high attention（高注意力）
  • clear goal（清晰目标）
  • acceptable risk（可接受风险）

形容词是属性，不是被归属的对象。

副词关联：当一个 RU 被使用或评估时，副词描述方式。

  • work efficiently（高效工作）——efficiently 修饰 work 的方式，但 efficiency 才是被评估的对象。

4.6.1 例外：动词形容词作为 RU 的边界情况

有些词虽然语法上是动词或形容词，但在使用中已被当作”一个东西”来指称。例如：

  • learning（学习）：动名词，但在日常使用中已被当作一个 RU——你可以讨论 learning 的方法、效率、目标。
  • feedback（反馈）：虽然是名词化的动词，但已在日常使用中成为标准 RU。
  • stress（压力）：名词化形容词的变体，但毫无疑问是 RU。

判断标准不是词性，而是能否通过五个 RU 标准。learning 可以通过所有五个标准。efficient 不能（你不能安置”高效”这个属性本身，只能安置 efficiency 这个概念）。

4.7 RU 的关联语言

每个 RU 在树上有一个位置。但它不是一个孤立的对象。RU 通过关联语言与其他单位连接。

关联语言包括：

  • 关联动作：针对这个 RU 的典型操作。attention → direct, maintain, shift, split；goal → set, pursue, achieve, abandon
  • 关联属性：描述这个 RU 的状态或特征。attention → sustained, focused, divided, scattered；goal → clear, vague, short-term, long-term
  • 关联状态：这个 RU 可能处于的状态。attention → high, low, depleted
  • 关联关系：这个 RU 与其他 RU 的关系。attention ↔︎ learning（高注意力促进学习），risk ↔︎ cost（高风险通常伴随高成本）
  • 关联评价：对这个 RU 的价值判断。workflow → efficient 或 inefficient（但 efficient 本身不是 RU）

关联语言不出现在主树结构中，但它们构成了 RU 的使用场景。

4.8 主位置与关联位置

一个 RU 通常有一个主位置。但有些 RU 天然跨越多个 Theme。

主位置：你在 RU 树中给它安排的最主要位置。

关联位置：它在其他 Theme 中的次要位置。

示例：

RU 主位置 关联位置
prompt Language → Instruction → Prompt Technology → AI Model → Model Input
feedback Work → Feedback Relationship → Communication
focus Mind → Attention → Focus Body → Energy → Mental Energy
risk Value → Risk Work → Decision
career Society → Career Work → Goal

规则很简单：

  1. 每个 RU 至少有一个主位置。
  2. 关联位置不超过 3 个。太多关联位置说明这个 RU 需要拆解或重新定位。
  3. 主树保持稳定。关联位置负责跨域连接。

4.9 示例：对一个新概念的 RU 评估

假设你刚学到”鲁棒性（robustness）“这个概念。

可指称？ 是的。“这个系统的 robustness 不够。”

可分类？ 属于 Technology → System，也可以属于 Value → Standard → Quality Standard。

可容纳？ 是的，它本身可以是一个 Container，收纳 fault tolerance、graceful degradation、redundancy 等。

可连接？ 和相关 RU 有关系：robustness ↔︎ reliability ↔︎ fault tolerance。

服务主体增益？ 如果你做系统设计、工程管理或技术决策，它直接服务判断和行动。

→ 通过。值得放入 Technology → System → Robustness。

4.10 常见误区

“所有名词都是 RU。” 不一定。特定领域的名词（如化学元素周期表里的稀有气体名）可能通过了前四个标准，但通常不通过主体增益筛选——你不需要在个人 RU 树里安置”氪”。

“所有抽象名词都是 RU。” 不一定。虚构概念（如”以太”）可以指称，但在现代科学语境下不服务于你的主体增益——除非你是科学史研究者。

“RU 太严格了，什么都进不去。” 如果你发现生活中几乎所有概念都通不过 RU 筛选，说明你没把自己的经验当主体。注意力、情绪、目标、方案、反馈、产品、用户——这些你都天天用。试着识别一下你日常思考和对话中最常被当作”东西”来讨论的语义单位。

4.11 训练方法

接下来三天，留意你在阅读和对话中遇到的词。每个词用五标准快速判断：

  1. 可指称？
  2. 可分类？
  3. 可容纳？
  4. 可连接？
  5. 服务主体增益？

把通过所有标准的概念记下来。一个概念一个笔记。不用马上给它找精确位置——那是第 3 章的事。

你可能会发现：真正的 RU 远比你想象中少。你真正需要安置的概念数量是有限的。这正是 RU 树有效的原因——它只安置值得安置的单位。

4.12 语言调用：RU 必须能被说出来

RU 的最终检验不是你能不能把它放在树上——而是你能不能在日常语言中调用它。

一个 RU 通过了五标准，被安置在某个位置，但它还没有进入你的语言能力。进入语言能力意味着：

  • 你可以在对话中自然使用它：“我的 mental energy 今天很低。”
  • 你可以在写作中精确使用它：“这需要更清晰的 acceptance criteria。”
  • 你可以在思考中用来自检：“这是我的 cognitive bias。”
  • 你可以在 AI 指令中使用它：“帮我设计一个 AI workflow。”

从第 7 章开始，每个 Container 都会附带”常见用法”板块——包含常见搭配和例句。那是你的语言调用训练场。

4.13 本章产物

RU 五标准检查表：

标准 问题 通过条件
可指称 能不能用”这个”“那个”指称它？ 是
可分类 有没有上层类别？ 有
可容纳 能不能装进某个容器或装下其他 RU？ 能
可连接 能不能和其他 RU 建立关系？ 能
主体增益 有没有通过四问筛选？ 通过

五个全通过 → RU，值得进入主树。前四个通过但第五个不通过 → 外部知识。

4.14 小结

RU 五标准是识别可指称单位的精确工具。记住：RU 不是按词性判断的，是按语义角色判断的。有了筛选标准和识别工具，下一章我们要解决”放在哪里”的问题——用四层结构为每个 RU 找到位置。
