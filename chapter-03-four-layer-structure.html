5  第 3 章：四层结构 — Theme → Group → Container → Leaf（Four-Layer Structure）

5.1 本章要解决的问题

你手上有一批通过主体增益筛选的 RU。现在的问题是：把它们放在哪里？

一个 RU 应该放在”生活”下面，还是”个人成长”下面？attention 属于 Mind 还是 Work？stress 属于 Body 还是 Mind？risk 属于哪个 Theme？

没有安置层级，RU 就是一堆标签，不是一个系统。

本章建立四层结构：Theme → Group → Container → Leaf。这是 RU 树的骨架。读完本章，你能给任何一个 RU 找到它的位置。

5.2 本章位置

第 1 章给了你筛选标准（什么值得进），第 2 章给了你 RU 判断工具（什么算一个单位），第 3 章给你安置框架（放在哪里）。三者依次递进，缺一不可。

5.3 四层结构总览

Theme（主题域）     个人生活的最大域
  └── Group（分组）    Theme 内部的 RU 大类
        └── Container（容器）  能收纳一批具体 RU 的上层抽屉
              └── Leaf（叶子）  具体 RU（不穷尽）

每一层回答一个不同的问题：

层级 回答的问题 示例
Theme 这个 RU 属于哪一大生活域？ Body / Mind / Language / Work
Group 在这个 Theme 中，它属于哪一组？ Body → Energy / Sleep / Diet
Container 它属于哪类具体单位？ Body → Energy → Physical Energy
Leaf 具体 RU 是什么？ stamina, vitality, fatigue level

5.4 Theme：RU 所属的大生活域

Theme 是本书的分区结构。它把一个完整的人的生活划分为八个大域，确保每个 RU 都有归属。

八个 Theme：

# Theme 中文 覆盖什么
1 Body 身体单位 精力、睡眠、饮食、运动、健康、感官、压力
2 Mind 心智单位 感知、注意、记忆、情绪、动机、认知、学习、自我
3 Language 语言单位 词、句子、文本、概念、问题、论证、叙事、指令
4 Work 做事单位 目标、计划、任务、方法、项目、练习、问题、反馈
5 Relationship 人际关系单位 连接、信任、边界、亲密、合作、冲突、影响
6 Society 社会单位 角色、群体、组织、制度、市场、规则、职业
7 Technology 技术单位 工具、软件、AI、数据、系统、平台、自动化、工作流
8 Value 价值判断单位 重要性、收益、成本、风险、目的、标准、伦理、意义

八大 Theme 覆盖了个人生活的主要方面。没有遗漏吗？不可能完美覆盖，但足够了。这八个域是经验验证的——它们覆盖了一个成年人在社会中生活、工作、学习、创造所需的核心概念域。

一个 RU 必须能归入至少一个 Theme。如果一个 RU 无法归入任何 Theme，要么它不是 RU，要么它属于外部知识层。

关于 Theme 的边界：有些 RU 天然跨域。feedback 既属于 Work → Feedback，也可以放在 Language → Argument（论证反馈）。处理方式是用主位置 + 关联位置，不做重复安置。

5.5 Group：Theme 内部的 RU 大类

Group 是 Theme 的下一级。它回答：在这个 Theme 下，RU 主要分为哪些大类？

同一个 Theme 下的 Group 互不覆盖。每个 Group 定位一个不同的”方面”。

每个 Theme 包含 8 个 Group。不是 8 个是魔数，是经验验证——太少则粒度不够，太多则不可内化。

Group 的作用：

  1. 导航：你在 Body 里找”sleep quality”——它应该属于 Body → Sleep → Sleep Quality。
  2. 连接：同一个 Group 下的 RU 通常有关联。Body → Energy 下的 Physical Energy、Mental Energy、Emotional Energy 是三种能量形式，它们相互影响。
  3. 筛选：如果一个 RU 不能归入任何现有 Group，要么它不是这个 Theme 的 RU，要么你需要在 Group 层面做调整——但不要随意新增 Group。

Group 是固定的吗？是。本书的 64 个 Group（8×8）是经过设计的。在个人使用中，你可以在 6 个月后再调整，但一开始不要频繁改 Group。固定结构帮助你快速安置。

5.6 Container：能收纳具体 RU 的上层容器

Container 是四层结构中最关键也最实用的层级。为什么？因为 Theme 和 Group 比较稳定（一个人不会频繁换生活域），Leaf 太多（你没法内化所有叶子）。Container 是最佳的内化粒度。

什么是好 Container？五个标准：

5.6.1 标准一：比 Group 更具体

Group 是大类，Container 是大类下的一个可操作单位。

Body → Energy 是 Group。Physical Energy、Mental Energy 是 Container。Physical Energy 比 Energy 更具体——你知道它指的是体力，不是所有形式的能量。

5.6.2 标准二：比 Leaf 更抽象

Container 不指向单个事物，而是指向一组同类事物。

button 是 Leaf。UI Component 是 Container——它收纳 button、input、dropdown、modal 等所有界面组件。

5.6.3 标准三：能直接收纳一批具体 RU

Container 是一个抽屉。你打开它，里面应该有一组 RU。

打开 Technology → Software → UI Component，你应该能看到 button、radio、input、table、modal。

5.6.4 标准四：看到它能自然想到一组例子

这是一个实用性测试。当一个 Container 名称合适时，不需要说明书，你就能猜到它里面有什么。

“Negative Emotion” → 焦虑、恐惧、愤怒、悲伤。 “Diagnostic Question” → “问题出在哪里？”“为什么会这样？”“我现在有什么选择？”

5.6.5 标准五：服务主体增益

Container 本身就是值得你内化的单位。你不一定要记住它里面的所有叶子，但记住 Container 本身就能帮你在大脑里建立结构化导航。

Container 的命名规则：名称应当直接表明它收纳什么。好的 Container 名称像好文件夹名——Tell me what’s inside。

5.6.6 Container 的语言调用

Container 不只是安置单元，也是调用单元。你在日常语言中说”我需要提高 sleep quality”——你调用了 Container。你说”这是我的 cognitive load 太高了”——你调用了 Container。Container 是你在语言中使用 RU 的常用粒度。

因此，从第 7 章开始，每个 Container 都会附带常见搭配和例句。因为 Container 的最终价值不在于它被定义得多清楚，而在于它被说出来时多自然。

5.7 Leaf：具体 RU

Leaf 是四层结构的最底层——具体可指称单位。Container 之下就是 Leaf。

Leaf 没有被一一列举。这是有意的设计决定：

  1. 叶子无限。 你无法穷尽所有 button 类型的 UI 组件。总是有新的、特定产品下的、还没分类的。Container 稳定，Leaf 流动。
  2. 内化重点是 Container。 你不需要记住所有 Leaf，只需要知道”UI Component 里有我需要的东西”。具体用哪个 Leaf 是搜索和识别问题，不是内化问题。
  3. 叶子可以随时添加。 你在工作中遇到一个新东西，判断它是 UI Component，直接把它放进去。不需要修改结构。

在本书中，Leaf 只在 Container 示例中出现，作为”这个容器装什么”的说明。

5.8 概念安置卡

概念安置卡是把一个 RU 放入树中的操作模板。格式如下：

RU 名称：
主位置：Theme → Group → Container
关联位置：（可选）
关联动作：（可选）
关联属性：（可选）
说明：

示例：

RU 名称：button
主位置：Technology → Software → UI Component
关联位置：—
关联动作：click, tap, hover, disable, enable
关联属性：primary, secondary, disabled, loading
说明：button 是所有界面交互中最基础的触发单位。
RU 名称：anxiety
主位置：Mind → Emotion → Negative Emotion
关联位置：Body → Stress → Stress Response
关联动作：feel, trigger, reduce, manage
关联属性：mild, moderate, severe, chronic
说明：anxiety 是对不确定威胁的情绪反应。

5.9 示例：完整的四层安置

以”focus”为例，走一遍安置过程：

RU 评估（第 2 章方法）： focus 可以通过所有五个标准。可指称、可分类（Mind → Attention）、可容纳（它本身就是 Container，收纳 deep work 状态、专注时长、注意力残留等）、可连接（focus ↔︎ attention ↔︎ energy）、服务主体增益。

位置确定：

层级 位置
Theme Mind
Group Attention
Container Focus
Leaf 示例 deep work, flow, concentration, attention residue

关联位置： Body → Energy → Mental Energy（因为专注依赖脑力水平）

概念安置卡：

RU 名称：focus
主位置：Mind → Attention → Focus
关联位置：Body → Energy → Mental Energy
关联动作：enter, maintain, lose, regain, sustain
关联属性：deep, shallow, sustained, broken
说明：focus 是注意力集中的状态和容器。

5.10 常见误区

“Container 和 Group 有什么区别？” Group 是 Theme 下的天然大类。Container 是 Group 下的一个可操作抽屉。Group 像是文件柜的一个抽屉层，Container 是里面的文件夹。Group 稳定，Container 可以根据需要调整。

“一个 RU 可以放在多个位置吗？” 可以。用主位置 + 关联位置，每个 RU 只在一个 Theme 下作为主位置，其他位置作为关联。不要把一个 RU 在多个 Theme 下重复安置为主。

“Leaf 需要内化吗？” 不需要。内化重点是 Container。Leaf 是调用时自然识别的。

“可以自己新增 Container 吗？” 可以。Container 是四层中最灵活的层级。本书给出的 Container 示例是起始推荐，不是限制。你完全可以为个人需求增加 Container，只要它通过五标准。

5.12 小结
